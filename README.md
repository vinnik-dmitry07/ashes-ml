# AHSL 1.4

Исполняемый эталон языка харнесов с Mission, наследованием гарантий родителя,
отдельным evaluator и проверкой механизма успеха перед обучением.

Python 3.11 или новее, только стандартная библиотека. Сначала прочитайте
`SPEC.md`; граница доверия — программа в ограниченном DSL, не произвольный
Python-код внутри процесса контроллера.

```bash
python3 verify.py
python3 demo.py
```

Проверка не переписывает фиксированные векторы или манифест. Если имеется
доверенный внешний хеш манифеста, используйте:

```bash
python3 verify.py --expected-manifest 1788f49943acc27113fdd554be5df8ec1c4d49c22985311d74f1ab97579b53a6
```

Не используйте `--write-manifest` при проверке полученного пакета: это флаг
сборки нового выпуска. Изменяемый verifier не удостоверяет сам себя;
аутентифицируйте архив или verifier внешним доверенным способом.

Содержимое:

* `SPEC.md` — нормативная спецификация.
* `CHANGELOG.md` — краткий список изменений 1.4.
* `AUDIT-CLOSURE.md` — решения по находкам аудита.
* `ahsl/` — язык, checker, runner, допуск и память.
* `examples/` — пять исполняемых программ.
* `protocol-schemas.json` — собственный метаязык структурных схем.
* `encoding-vectors.json` — зафиксированные байтовые векторы.
* `tests/` — проверки контрактов и состязательные сценарии.
* `reports/verification.json` — фактические результаты проверок.
* `reports/benchmark.json` — двенадцать уровней, пять повторов на метод.
* `reports/demo.json` — полный цикл исполнения, допуска и конденсации.

Демонстрационные HMAC-ключи публичны и служат только для воспроизводимых
локальных тестов. В сервисе ключ, полномочия и якорь снимка принадлежат
доверенному владельцу.

Выпуск не содержит Lean, моделей LLM, обучения весов, ускорения KV или
внешних сервисов. Их место и обязательства определены в §18 спецификации.

Проверено: 83 теста (16 новых регрессий), 6480 состояний K12; после конденсации новая
программа прошла полный допуск на 12/12 уровнях. Разделение ключей
observer/evaluator в эталоне логическое, в одном доверенном процессе.

В 1.4 исправлены обход AST в `trim_alias` и кодируемость глубоких программ
в снимке. Отдельно расширен `improve`: после полного успеха принимается
строгое Парето-улучшение действий, VM fuel и размера программы при
сохранении всех обязательных гарантий. Демонстрация выполняет три выпуска
на 12 уровнях, включая второе improve, и учитывает все 72 эпизода.

Снимки, content IDs и производные ключи принадлежат версии 1.4.
Автоматической миграции свидетельств из 1.3 нет; нужен новый bootstrap.
Дополнительные требования к исследовательскому адаптеру описаны в
§14.1–14.4 и §15.1; готового TRIZ-решателя или mG-Pass@k gate в пакете нет.
