# Подробное ревью AHSL: что добавляет полная стенограмма

Проверено 11 сентября 2026 года. Материалы: `brief.md`, `AHSL-specification-v1_5.md`, `transcript (1).md`. Номера реплик ниже относятся к заголовкам стенограммы, например «№183».

**Основной результат:** существенные пропуски есть прежде всего в исследовательских выводах, которыми обосновывается архитектура. Проверка отдельных утверждений о коде не проверяет переходы «теорема → архитектурное ограничение», «результат статьи → универсальный механизм» и «наблюдаемый score → гарантия». Несколько таких переходов неверны; другие пока остаются гипотезами.

Это ревью документов и первоисточников. Исполняемый пакет AHSL не приложен, поэтому числа тестов, трассы атак и соответствие Python спецификации здесь независимо не воспроизведены. Пересказы запусков в стенограмме не заменяют исходники и полные результаты. Численные контрпримеры в этом отчёте вычислены отдельно.

## 1. Латентная рекуррентность ошибочно исключена теоремой о фиксированной глубине

**Где:** №183. **Статус:** ошибка области применимости теоремы; меняет выбор исследовательского направления.

В ответе сначала рекуррентность отождествляется с фиксированным числом слоёв, затем делается вывод: «Явные токены — единственный способ получить неограниченную последовательную глубину».

В использованной работе Merrill и Sabharwal глубина трансформера фиксирована относительно длины входа. Это прямо оговорено в определении модели. Повторяемый блок с переменным числом итераций не удовлетворяет этой предпосылке. Кроме того, некоторые используемые разделения классов сложности являются общепринятыми предположениями, а не доказанными неравенствами. [The Parallelism Tradeoff, определение 12 и обсуждение ограничений](https://arxiv.org/pdf/2207.00729).

Контрпример к слову «единственный» существует на уровне архитектуры: recurrent-depth модели наращивают вычисления, повторяя блок в латентном пространстве перед выдачей токена. Это явно исследуется в работе о Huginn; более ранний Universal Transformer также использует рекуррентность по глубине. [Scaling up Test-Time Compute with Latent Reasoning](https://arxiv.org/abs/2502.05171), [Universal Transformers](https://arxiv.org/abs/1807.03819).

**Корректная замена:** фиксированная глубина одного прохода ограничивает последовательное вычисление; увеличить его можно дополнительными токенами, повторными латентными итерациями или внешними вызовами. Их качество, стоимость и обучаемость надо сравнивать отдельно.

Это не доказательство, что латентное рассуждение будет лучше CoT. Но исходное теоретическое основание для его исключения несостоятельно. Особенно существенно это для исходного замысла пользователя о непрерывном латентном поиске.

## 2. GEPA ошибочно помещена только во внешний цикл; DAG ошибочно объявлен статическим

**Где:** №183, сравнительная таблица. **Статус:** фактическая ошибка по GEPA и чрезмерное ограничение понятия DAG.

GEPA описывается как оптимизатор харнеса, который не работает внутри решения текущего экземпляра. Однако §5.1 статьи прямо посвящён поиску во время инференса: оптимизации кода для NPUEval и KernelBench. Это достаточно для опровержения категорического ограничения. [GEPA, §5.1 Inference-Time Search](https://arxiv.org/pdf/2507.19457).

Аналогично, DAG означает отсутствие ориентированных циклов, а не фиксацию всех узлов при авторстве. Граф можно наращивать во время исполнения, сохраняя ацикличность. Статический workflow — частный случай DAG.

**Что изменить:** классифицировать отдельно алгоритм предложения кандидатов, момент его применения, способ хранения контекста, изменяемый объект и топологию исполнения. Эти оси не образуют взаимоисключающие классы «CoT / RLM / DAG / GEPA».

## 3. «Теорема об обёртке» не даёт заявленной гарантии

**Где:** №181, затем №200 и №218; бриф §2.3. **Статус:** математически неверное утверждение при перечисленных предпосылках. Предыдущее замечание сохраняется.

Честный внешний gate, скрытая выборка и учёт стоимости не устраняют ошибку конечного отбора. Даже при бесплатном отборе:

- Есть две руки с истинными вероятностями успеха 0,9 и 0,8.
- Каждая получает одно независимое честное испытание; при равенстве выбирается первая.
- Худшая рука выбирается, когда первая провалилась, а вторая преуспела: вероятность 0,1 × 0,8 = 0,08.
- Качество выбранной руки на новом испытании равно 0,92 × 0,9 + 0,08 × 0,8 = **0,892**, что меньше 0,9.

Все заявленные условия соблюдены. Следовательно, включение Ральфа в пространство кандидатов не делает проигрыш Ральфу невозможным. Разделение supervisor/candidate из Ouroboros также не закрывает статистический разрыв.

Возможна условная корректная формулировка. Пусть для всех K фиксированных кандидатов одновременно выполняется `|μ̂_i − μ_i| ≤ ε`, а выбран максимум μ̂. Тогда:

\[
\mu_{\hat i}\ge\max_i\mu_i-2\varepsilon.
\]

Вероятность этого события и размер ε зависят от выборки и протокола. Адаптивный поиск требует отдельного контроля. При общем бюджете B оценивать надо руки с оставшимся бюджетом B−C и сравнивать с базовым методом при полном B. Доллары нельзя непосредственно вычитать из accuracy без определения общей функции полезности.

В №181 присутствует и обратная крайность: превосходство объявляется принципиально недоказуемым без полного распределения LLM и стохастического доминирования. Для сравнения ожидаемой полезности доминирование не необходимо; при заданных предпосылках возможны вероятностные границы и гарантии относительно baseline. Это отличается от безусловной гарантии на произвольных будущих задачах. Пример такой условной постановки: [Conservative Contextual Linear Bandits](https://arxiv.org/abs/1611.06426).

## 4. Не установлена цепочка «не выражается RLM → не выражается Ральф»

**Где:** №181; бриф §2.3. **Статус:** пропущенное доказательное звено.

Непрохождение примеров RLM и GRPO и отсутствие инструкции `call` не доказывают невозможность простого Ralph-loop. Цикл перезапуска промпта с файловой памятью и рекурсивные модельные вызовы требуют разных возможностей. Возможно, конкретный профиль действительно не выражает нужный Ralph-loop, но это надо показать на его операционном контракте.

Нужен конкретный список обязательных операций Ральфа и отображение каждой операции в язык или доказанное препятствие. Проценты выразимости пяти примеров сами по себе не являются мерой универсальности.

**Для 1.5:** рекурсия и локальная конденсация уже заявлены. Старые отказы версии 1.0 не следует переносить на текущую версию. Одновременно текущие примеры языка, как справедливо говорит сама спецификация, не воспроизводят результаты внешних харнесов.

## 5. mG-Pass@k не гарантирует нижний хвост качества и не исключает Goodhart

**Где:** №101, №179, №181, №229. **Статус:** неверная интерпретация корректной метрики.

В стенограмме формула `E[p^k] ≠ E[p]^k` и неравенство Йенсена уже известны. Проблема не в незнании формулы, а в выводе, что усреднение этой линии метрик обеспечивает нижний хвост и защиту от reward hacking.

Возьмём задачи равного веса и независимые повторы внутри каждой задачи:

| Свойство | Система A | Система B |
|---|---:|---:|
| Вероятность успеха на задаче | 0,8 на каждой | 1 на 80% задач, 0 на остальных |
| Средний pass@1 | 0,8 | 0,8 |
| Средний pass³ | 0,512 | 0,8 |
| Средний mG-Pass@4 | 0,6144 | 0,8 |
| 10-й процентиль истинных вероятностей успеха по задачам | 0,8 | 0 |

Для определения с чётным k, используемого в 1.5:

\[
mG_4(p)=\tfrac12\left(\Pr[C_4\ge3]+\Pr[C_4=4]\right)
=2p^3-p^4,
\]

где `C₄ ~ Binomial(4,p)`. При p=0,8 получаем 0,6144. Для B значение равно 0,8 × 1 + 0,2 × 0 = 0,8.

Метрика закономерно вознаграждает повторяемый успех на уже решаемых задачах. Из этого не следует покрытие трудных задач: она может предпочесть систему с постоянной слепой зоной. Это не дефект формулы авторов, а ограничение её использования как единственного критерия. [Авторское определение G-Pass@k](https://aclanthology.org/2025.findings-acl.905/).

Усреднение порогов исключает выбор одного удобного τ после опыта, если остальные настройки закреплены. Оно не исключает подмену judge, выбор удобных задач, утечки, смену k или адаптивное переобучение на оценке.

Ещё две связанные ошибки:

- `pass^k` не является логическим дополнением `pass@k`: «все успешны» и «хотя бы один успешен» не противоположные события. При p=0,8 и k=3 это 0,512 и 0,992.
- Разрыв горизонтов 50% и 90% по смеси задач не равен нестабильности прогонов. Он может отражать разные детерминированные сложности задач.

**Что измерять:** отдельно повторяемость внутри задачи, распределение вероятностей успеха между задачами и разброс полных циклов поиска. Для нижнего хвоста требуется определить, по какой именно случайной величине берётся квантиль.

**Для 1.5:** §15.1 уже прямо отказывается от обещания anti-Goodhart и от автоматической гарантии будущего покрытия. Не следует объявлять старое обещание действующим свойством этой версии.

## 6. Порог атомарности не является сертификатом композиции

**Где:** №183; бриф §2.5. **Статус:** недостаточные условия предлагаемого критерия. Предыдущее замечание сохраняется.

`pass@1(u) ≥ θ` — полезное операционное определение надёжности блока в объявленном контексте. Оно не доказывает надёжность композиции из блоков.

Даже при независимых ошибках двадцать шагов с вероятностью успеха 0,95 каждый дают полный успех только `0,95²⁰ ≈ 0,3585`. Без независимости нужны оценки на распределении входов, которое создают предыдущие шаги, а не только на отдельном бенчмарке атома.

Нужны как минимум совместимость выходного и входного контрактов соседних блоков, бюджет общего риска, проверка побочных эффектов и наблюдаемые условия остановки/восстановления. Для адаптивной декомпозиции эти условия должны относиться и к выбранным ветвям.

Дешёвый «один замер» не означает статистически уверенный порог. При заранее фиксированном IID-испытании и отсутствии ошибок односторонняя 95%-я нижняя граница достигает 0,95 после **59** успехов подряд, а 0,99 — после **299**. Поиск среди многих атомов и повторный выбор по тем же данным требуют дополнительных поправок.

**Корректная замена:** атомарность — локальное эмпирическое свойство `(блок, модель, входное распределение, контекст, бюджет, версия)`. Сертификат декомпозиции должен отдельно устанавливать, что успех её частей влечёт цель и что общий риск приемлем.

## 7. Replay-fit, достоверность свидетельства и причинный вклад смешиваются

**Где:** №29, №61, №200, №229. **Статус:** переход от более слабого свидетельства к более сильному.

**Replay-fit.** Совпадение симулятора с конечным журналом не сертифицирует ненаблюдавшиеся переходы. Две модели могут совпадать на всём логе и расходиться на следующем действии. Поиск внутри такой модели условен относительно её предположений. В описании arc-skill есть полезные пошаговые guard-проверки и прерывание при расхождении; это снижает последствия ошибки, но не превращает модель в доказанно правильную для будущего.

**Review и хеш.** Привязка review к точному diff защищает от подмены проверяемого снимка. Она удостоверяет, что оценивали этот артефакт, но не устанавливает истинность мнения оценщика. Поэтому №200 не обосновывает конъюнкт `∀I ∈ preserved(parent): candidate ⊨ I` одним лишь snapshot-bound review и наличием конституции в контексте.

**Прогноз и causal credit.** Правильное предсказание результата не доказывает причинную необходимость действия. Можно правильно предсказать неизменное состояние после бесполезного `noop`. Для утверждения о вкладе нужны интервенция, абляция или иной объявленный причинный критерий.

Полезно различать четыре статуса: «пришло от уполномоченного источника», «прошло проверку на наблюдённом пути», «гарантировано в объявленном домене», «имеет установленный причинный вклад».

**Для 1.5:** важная часть уже исправлена текстом: §11 вводит `FIT_ON_LOG`, §13 отделяет `prediction hit` от `causal credit` и ограничивает доказанное допустимостью пути и достижением цели. Это исправления, которые надо сохранить, а не заново записать в список пропусков.

## 8. PoLar: существование короткого пути не доказывает полезность адаптивного выбора

**Где:** №218 и сохраняемый вывод №227. **Статус:** ошибка кванторов; исправление числа её не устранило.

Результат «для 71,9% исходно правильно решённых входов существует более короткая корректная программа» не означает «на 71,9% входов меняется победитель» и тем более не означает «обучаемый selector лучше любой фиксированной политики». [PoLar, актуальная версия и приложение об исправлении сплита](https://arxiv.org/pdf/2606.06574).

Логически различаются:

1. Для многих x существует подходящий короткий путь `a(x)`.
2. Лучший путь действительно различается между x.
3. По доступным до решения признакам можно выбрать этот путь.
4. Выигрыш выбора превышает стоимость его поиска.

Первое не доказывает остальные. Например, один и тот же фиксированный короткий путь может работать на всех входах из указанной доли.

Сходная ошибка присутствует в тезисе №181 «позадачный argmax меняется → selector побеждает». Это даёт потенциальный выигрыш oracle на рассматриваемом портфеле, а не достижимый выигрыш обученного маршрутизатора. При шумных единичных прогонах даже наблюдаемая смена победителя может быть шумом.

Отдельная фактологическая правка: arXiv содержит v1 и исправленную v2; наличие новой версии и исправление дублей не равны формальному отзыву статьи. Лучше писать «числа из прежней версии с загрязнённым сплитом», а не «из отозванной версии». [История версий PoLar](https://arxiv.org/abs/2606.06574).

## 9. Meta-Harness: «5,5 задач-эквивалентов регрессии» не следует из данных

**Где:** №227. **Статус:** самостоятельная арифметико-логическая ошибка, не исправленная признанием ложной цитаты.

В стенограмме сказано: улучшения на 7 из 89 задач при нетто +1,7 п.п. означают около 5,5 задач-эквивалентов регрессии. Статья действительно обсуждает улучшения на семи задачах, но число улучшившихся задач не равно сумме приростов их вероятностей успеха. [Meta-Harness, приложение B.3](https://arxiv.org/html/2603.28052v1).

Если Δᵢ — изменение success rate задачи, то:

\[
\sum_i\Delta_i=89\cdot0{,}017\approx1{,}513.
\]

Обозначим суммарный положительный прирост через G, суммарные потери через L. Тогда `G−L≈1,513`. Если положительных задач семь, известно лишь `G≤7`; следовательно, `L≤5,487`. Это **верхняя граница**, а не установленный объём потерь.

С этими числами совместимо отсутствие регрессий: семь задач улучшаются примерно на 0,216 каждая, остальные не меняются. Для фактического L нужны все позадачные дельты. Округление агрегатных процентов добавляет небольшую погрешность, но не меняет логику.

## 10. Тезис «польза харнеса сжимается с горизонтом» остаётся недоказанным

**Где:** №181, №218, №227. **Статус:** причинное обобщение из несопоставимых сравнений.

Автор стенограммы правильно признал выдуманную атрибуцию Meta-Harness. Но затем сохранил причинный вывод и объявил его усиленным.

Сравнение +7,7 п.п. на классификации и +1,7 п.п. на Terminal-Bench одновременно меняет семейство задач, базовый уровень, модель/режим, базовый харнес и характер модификаций. Из него нельзя выделить влияние горизонта. Ни меньший контекст, ни хороший результат сами по себе также не измеряют «locally in-distribution».

Утверждение «побеждает минимальное» опирается на такую же проблему определения переменной. В №45 названы **129 строк SKILL и 4343 строки CLI**; позднее основным показателем размера становятся 129 строк и число видимых инструментов. Один `python` может предоставлять неограниченно сложное поведение. Короткий интерфейс не измеряет вычислительную ёмкость или сложность всей системы.

Аргумент через сильный Goodhart тоже недостаточен: в обсуждаемой модели зависимость от ёмкости немонотонна, и увеличение ёмкости рассматривается также как возможное смягчение. Из неё не следует «больше стадий харнеса → хуже». [Sohl-Dickstein, Strong Goodhart](https://sohl-dickstein.github.io/2022/11/06/strong-Goodhart.html).

**Что сохранилось:** минимальный рабочий baseline полезен как инженерная отправная точка. **Что надо снять:** выдачу его предполагаемого преимущества за установленный общий закон.

## 11. Ouroboros: знак разницы и смысл p-value

**Где:** №200. **Статус:** фактическая ошибка направления и слишком сильная статистическая интерпретация.

После фильтрации SWE-bench Pro статья сообщает **58,2% у Ouroboros и 59,4% у Codex**, то есть Ouroboros уступает на 1,2 п.п. В стенограмме это названо «паритетом при отрыве в 1,2 пункта». Для 655 парных задач указан McNemar `p=0,40`. [Ouroboros, результаты SWE-bench Pro](https://arxiv.org/html/2608.08311v3).

Незначимость различия не доказывает эквивалентность. Для утверждения об эквивалентности или не меньшей эффективности нужны заранее заданный практически допустимый разрыв и соответствующий интервал/тест. Формулировку «parity» используют и авторы статьи; это не исключительно ошибка пересказа, но статистический вывод всё равно надо ограничить.

Есть ещё две границы интерпретации:

- Замороженная ветка решает воспроизводимость версии, скрытая выборка — контроль отбора и утечек. Это разные задачи; первая не является более чистой заменой второй.
- Симметричное исключение задач, где какая-либо сторона дошла до эталонного исправления, полезно для аудита загрязнения. Но оценка после такого исключения относится к отобранному подмножеству, а не автоматически ко всему исходному benchmark.

Для 5 × 89 испытаний важно также объявить объект статистического вывода: повторы на фиксированных задачах или перенос на новые задачи. Одна биномиальная SE по 445 исходам не закрывает все источники неопределённости и не равна стандартной ошибке разности с чужим baseline.

## 12. KV-перенос не обязан увеличивать корреляцию ошибок

**Где:** №218. **Статус:** ложная необходимость; требуется измерение.

Фраза «KV-перенос увеличивает корреляцию по построению» не обоснована. Рассмотрим точное преобразование, которое выдаёт получателю тот же KV-cache, который он вычислил бы самостоятельно. При прежнем входе, декодере и случайности поведение получателя не меняется. Значит, не меняется и его корреляция ошибок с другими участниками.

Для приближённого отображения корреляция может измениться в любую сторону. Одинаковый исходный документ уже является общим источником информации даже без передачи кэша. Обсуждаемая работа действительно рассматривает замену повторного prefill отображением кэша. [Cross-Model KV Transfer](https://arxiv.org/html/2608.03893v1).

**Что измерять:** на одних задачах сравнить самостоятельный prefill и перенос; оценить точность каждого участника, совместные ошибки и итоговое решение совета. Один `effective_n` не описывает все вероятности совместного провала: одинаковая попарная корреляция не фиксирует всю совместную структуру.

Этот пункт не доказывает, что KV-перенос безопасен или полезен для конкретного совета. Он снимает ошибочный априорный запрет.

## 13. В стоимости «20 рук за $0,014» отсутствует объём оценки

**Где:** №218. **Статус:** неполный расчёт, использованный для смены вывода.

Из заявленной цены `$0,0007` за задачу следует `$0,014` за двадцать таких единичных вычислений. Но не за поиск двадцати кандидатов с оценкой на достаточном скрытом наборе.

Даже при переносимости этой цены двадцать кандидатов на ста оценочных задачах стоят `20 × 100 × $0,0007 = $1,40`. Это ещё без конструирования кандидатов, judge, повторов и возможной потери качества относительно более сильного baseline.

Поэтому экономический вопрос не закрыт арифметикой одной генерации. При этом небольшая цена действительно может сделать более качественный опыт доступным; вывод должен следовать из полного бюджета конкретного протокола.

## 14. Аудит «50 → 1» не является калибровкой и контрфактуалом DeepMind

**Где:** №158, №171, №200, №216; бриф §2.1 и §2.7. **Статус:** ошибка интерпретации уже имеющихся категорий.

В №158 явно существуют отдельные поля `reproduces` и `disclosed_at`. Значит, проблема не в полном отсутствии классификации: при итоговом агрегировании были смешаны разные ответы.

| Состояние находки | Что можно заключить |
|---|---|
| Факт не воспроизводится или вывод опровергнут | Аргумент за ошибочность находки |
| Факт реален, но ограничение уже раскрыто | Находка может быть не новой; это не делает факт ложным |
| Требование не нарушено при заявленных предпосылках | Не дефект соответствия этому профилю |
| Свидетельств недостаточно | Неопределённость, а не установленная ложность |

Поэтому 49 отклонённых замечаний не означают 49 ложных срабатываний. При указанной разбивке около 30 относятся к раскрытым ограничениям. «2% выживаемости» — свойство этого процесса фильтрации, не оценка чувствительности аудита или надёжности AHSL.

Сравнение собственной сессии с кейсом DeepMind также не является контролируемым контрфактуалом. Меняются задачи, стимулы, модели, критерий успеха и механизм проверки. Оно иллюстрирует гипотезу о роли принуждения, но не измеряет её эффект.

Две важные фактологические оговорки по первоисточнику: агенты имели общую модель и правило честности, но получали одну из **четырёх случайно назначенных математических персон**, поэтому «идентичные промпты» в брифе слишком сильно. В №216 оговорка про доменные персоны есть; при сжатии она потерялась. Авторы **явно сообщают о последующих независимых воспроизведениях** заражения и whistleblowing; объявлять исследование единственным запуском тоже было бы ошибкой. Числа повторов и их распределения в этом сообщении не установлены. [DeepMind, §2.1 и начало §3](https://arxiv.org/html/2609.04170v1).

**Как оценить смещение без полного повторного аудита:** взять небольшую стратифицированную выборку из существующих категорий, скрыть предыдущий вердикт, независимо проверить буквальное утверждение и нарушение нормы как два разных вопроса. Добавить заведомо истинные и заведомо ложные контрольные утверждения. Отдельно считать пропуск реального дефекта, ложное обвинение и признание известного ограничения новым. Если выборка стратифицирована, общую долю оценивать с её весами. Маленькая выборка даст широкие интервалы, но уже проверит направление смещения.

## 15. «Мутация верификатора — единственный необратимый ход» неверна

**Где:** №101 и №216; бриф, вопрос 6. **Статус:** ложная категоричность, создающая искусственное противоречие с изменением правил.

Изменение верификатора можно версионировать, откатить и повторно оценить сохранённые артефакты. Удаление единственных данных, внешнее действие или публикация секрета могут быть необратимы и без изменения верификатора. Само слово «мутация» не определяет обратимость.

Реальная опасность другая: потерять доверенный критерий, смешать несопоставимые серии оценок или позволить кандидату самому ослабить условия своего допуска.

Разрешение: отдельное полномочие на новую версию evaluator; сохранение старой версии и исходных свидетельств; привязка каждого verdict к версии; явное правило перехода и переоценки. Право предложить изменение действительно можно отделить от права утвердить его. Но неизменность кода верификатора навсегда не является единственным возможным решением.

В 1.5 уже предусмотрен доверенный путь смены verifier. Это совместимо с указанным разграничением.

## 16. Два общих вывода надо сузить, а не «опровергнуть обратным»

**Только RL учит композиции.** Эксперимент с конкретной моделью, функциями, данными и вариантами RL/RFT/SFT поддерживает сравнительный результат в этом протоколе. Он не устанавливает универсальную необходимость RL. Отдельно верно замечено в №183: исполнение данной композиции не равно поиску композиции. [Исследование f∘g](https://arxiv.org/html/2509.25123v1).

**Отсутствуют error bars → n=1 → эффекта нет.** Если число независимых запусков не раскрыто, его следует пометить как неизвестное. Если статистическая неопределённость не оценена, нельзя объявлять ни доказанное улучшение, ни доказанное отсутствие улучшения. Это относится к формулировкам «в пределах ничего» и «ничего на сходимости». При этом вопрос о практической значимости небольшого эффекта вполне уместен.

Для работ об ускорении сильнейший baseline только по accuracy тоже не всегда достаточен. Нужна точность вместе со стоимостью/latency при сравнимых ограничениях. Это не оправдывает слабый контроль; это уточняет, какой вопрос контроль должен отвечать.

## 18. Что относится к текущей AHSL 1.5

В тексте 1.5 есть одно прямое несоответствие идентификатора: §12.1 закрепляет в Mission `SUCCESS_THEN_PARETO_COST_1`, а §12.3 определяет актуальный профиль `SUCCESS_THEN_PARETO_COST_2`.

Это не безобидная редакционная деталь: профиль входит в Mission, а Mission хешируется и закрепляется. Нужны согласованные значение, примеры и векторы. По одному Markdown нельзя установить, какая строка используется реальным bootstrap. Поэтому это **подтверждённое расхождение текста**, а не доказанный эксплойт реализации.

Напротив, в 1.5 уже явно сформулированы границы, которые ранние ответы нарушали:

- свидетельство observer и оценка evaluator разделены, но исходная достоверность наблюдения остаётся предпосылкой;
- `FIT_ON_LOG` не сертифицирует будущее;
- точность прогноза не является causal credit;
- mG не объявлена защитой от Goodhart;
- retain требует абсолютного успеха в закреплённом конечном домене;
- конечный пример G12 не объявлен доказательством преимущества на внешних агентных задачах.

Это делает текущий документ существенно осторожнее исторических выводов. Проверка соответствия реализации этим положениям потребует пакета исходников и тестовых артефактов.

## 19. Что закрыть за неделю

Первая цель — получить измеримый ответ о пользе метода построения харнеса. Формальная корректность экземпляра и качество процедуры, создающей экземпляры, — разные свойства.

Удобно явно задать:

\[
G:(TaskSpec,EnvContract,Capabilities,B)\longrightarrow H.
\]

AHSL описывает и проверяет H. Исследовательское обещание относится к G: насколько хорошие H он создаёт на новых задачах с учётом расходов на поиск, оценку и исполнение. Проверка H не доказывает качество G.

| Период | Работа | Результат для решения |
|---|---|---|
| День 1 | Исправить перечисленные категорические выводы; выбрать одно семейство задач и определить полный бюджет | Проверяемая гипотеза вместо обещания невозможности проигрыша |
| Дни 2–3 | Реализовать Ralph, Ralph с тем же gate и декомпозицию с тем же gate; закрепить модель, инструменты, данные и бюджет | Разделение эффекта gate и эффекта декомпозиции |
| Дни 4–5 | Повторить полные циклы на отложенных задачах; сохранять отказы и расходы | Среднее качество, повторяемость, покрытие задач и стоимость |
| День 6 | Сопоставить обучаемый selector с лучшей фиксированной рукой; oracle показывать отдельно | Реализуемый выигрыш выбора и его верхняя граница |
| День 7 | Проверить несколько ключевых отклонённых находок вслепую и принять решение по заранее заданному критерию | Оценка направления аудиторского смещения и выбор следующей работы |

Минимальный отчёт опыта: качество при одинаковом полном бюджете; частота общих провалов; результаты по задачам и по повторам; стоимость отбора; неопределённость парной разности. Если нижний хвост заявлен целью, его определение и метод оценки фиксируются заранее.

Решение о латентной рекуррентности не стоит объединять с этим опытом автоматически: сравнение разных обученных архитектур вносит свои смешивающие факторы. Но исключать это направление на основании №183 уже нельзя.

## Приложение. Воспроизводимые численные проверки

Код ниже проверяет арифметику контрпримеров. Это не тесты реализации AHSL и не воспроизведение внешних экспериментов.

```python
from fractions import Fraction
from math import ceil, comb, log


def mg_probability(p, k):
    return Fraction(2, k) * sum(
        sum(
            Fraction(comb(k, j)) * p ** j * (1 - p) ** (k - j)
            for j in range(threshold, k + 1)
        )
        for threshold in range(k // 2 + 1, k + 1)
    )


for denominator in range(1, 31):
    for numerator in range(denominator + 1):
        q = Fraction(numerator, denominator)
        assert mg_probability(q, 4) == 2 * q ** 3 - q ** 4

p = Fraction(4, 5)
assert p ** 3 == Fraction(64, 125)
assert 1 - (1 - p) ** 3 == Fraction(124, 125)
assert mg_probability(p, 4) == Fraction(384, 625)

selection_quality = (
    Fraction(92, 100) * Fraction(9, 10)
    + Fraction(8, 100) * Fraction(8, 10)
)
assert selection_quality == Fraction(223, 250)
assert ceil(log(.05) / log(.95)) == 59
assert ceil(log(.05) / log(.99)) == 299
assert Fraction(7) - Fraction(17, 1000) * 89 == Fraction(5487, 1000)

print('All numerical counterexamples verified.')
```

Вероятности в примерах заданы явно. Формула mG проверена перебором 495 рациональных значений p, а тождество также получено алгебраически. Статистические размеры выборок относятся к фиксированным IID-испытаниям без адаптивного отбора и множественного тестирования.
