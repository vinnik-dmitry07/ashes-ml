# AHSL 1.5: воспроизведение реализации и готовность эксперимента

11 сентября 2026. Проверены приложенный `AHSL-1.5(2).zip` и найденный среди файлов пользователя `AHSL-LLM-experiment-0.3.zip`, на который ссылается README первого пакета.

**Результат:** штатные проверки воспроизводятся. Дополнительно найден дефект L12: корректная программа в объявленных пределах глубины и fuel вызывает `RecursionError`, а в G12 оставляет оценку незавершённой. Подготовлен отдельный патч, прошедший 98 прежних и четыре новых теста. Запрошенное сравнение Ralph / Ralph с gate / декомпозиция с тем же gate в этих пакетах ещё не реализовано. Сохранённые эксперименты используют программный имитатор; новых вызовов LLM при этом ревью не было.

## 2. Подтверждённый дефект: стек Python ограничивает L12 раньше спецификации

**Места:** `ahsl/language.py:execute`, `ahsl/environment.py:Runner._run`, `ahsl/api.py:_dispatch`, `ahsl/admission.py:Session.evaluate`. Норма — §5 `SPEC.md`.

Спецификация разрешает рекурсивные вызовы глубиной до 64, при fuel до 100000. Исполнитель рекурсивно вызывает Python-функции `invoke` и `evaluate`. На каждом уровне вызова L12 вложенные выражения создают дополнительные кадры Python. Поэтому ограничение глубины L12 не ограничивает стек Python тем же числом.

### Минимальный пример и контроль

Программа содержит функцию `loop(n)`, которая возвращает 0 при n=0, иначе вызывает `loop(n−1)`. Вокруг тела расположены 16 типизированных `let` с неиспользуемой целочисленной константой. Вход — n=60.

| Параметр | Значение | Объявленная граница |
|---|---:|---:|
| Максимальная глубина вызовов L12 | 62 | 64 |
| Глубина полного wire-объекта | 27 | 32 |
| Размер wire-запроса | 1857 байт | 131072 байта |
| Требуемый fuel при успешном исполнении | 2439 | В запросе предоставлено 50000 |

Программа проходит `check`, каноническое кодирование и внешнюю границу wire. При стандартном `sys.getrecursionlimit() == 1000`:

- прямой `execute` выбрасывает **RecursionError**;
- `run_pure` возвращает **SCHEMA**;
- при 12 вложенных `let` аналогичная программа исполняется: result=0, fuel=1951;
- при диагностическом увеличении стека Python до 5000 исходная программа с 16 `let` исполняется: result=0, fuel=2439.

Последний контроль меняет только стек хоста. Код программы, семантика L12 и её собственные лимиты остаются прежними. Увеличение стека использовано для установления причины, а не предложено как исправление.

### Последствия в G12

Тот же вызов добавлен перед обычным действием корректного corridor solver. Размер программы — 3094 байта. Для допустимого bootstrap с обязательным уровнем `[1]`:

| Шаг | Исходная 1.5, стек Python 1000 | Контроль, стек Python 5000 |
|---|---|---|
| `propose` | OK | OK |
| `evaluate` | **SCHEMA** | OK |
| Работа родителя | DONE | DONE |
| Работа кандидата | **RUNNING** | DONE |
| `open_runs` после оценки | **1** | 0 |
| Повтор `evaluate` | **PHASE** | Не требуется |
| Достижение цели и выпуск | Оценка не завершена | Принято: 4 действия, 9842 fuel |

Причина незавершённости: `Runner._run` обрабатывает `Rejected`, но не `RecursionError`. Исключение доходит до общего обработчика `_dispatch`, который выдаёт SCHEMA. Обработчик не завершает работу и не закрывает открытый run.

**Граница дефекта:** это ошибка исполнения и доступности сессии. Неверного положительного допуска и нарушения бюджетного инварианта этим примером не получено. В состоянии после отказа один билет потрачен, один зарезервирован, шесть свободны: всего восемь.

Штатный доверенный `Session.abandon(plan)` восстанавливает возможность работы: RUNNING становится SEALED, списывается второй билет, `open_runs` становится 0. После этого обычный solver успешно проходит новый выпуск. Значит, отказ не является необратимым повреждением; требуется действие supervisor, которого нет в агентском wire-наборе.

**Почему это существенно для предлагаемого опыта:** рекурсивная стратегия может проиграть из-за неучтённого ограничения интерпретатора. Такой отказ нельзя интерпретировать как свидетельство о качестве декомпозиции или модели.

## 3. Подготовлен отдельный патч

`fix-recursion.patch` в комплекте меняет три файла:

1. `ahsl/language.py`: заменяет рекурсивное исполнение явным стеком продолжений и значений. Глубина L12 по-прежнему ограничена 64; fuel списывается за те же AST-выражения.
2. `tests/test_recursion_boundary.py`: добавляет четыре теста.
3. `SPEC.md`: исправляет идентификатор профиля в примере Mission на `_2`.

Новые тесты проверяют:

- выполнение допустимой рекурсивной программы с точным результатом и fuel;
- сохранение настоящих ограничений FUEL и LIMIT;
- завершение G12-оценки и допуск корректного рекурсивного кандидата;
- порядок эффектов: поля записей по ASCII-именам, аргументы слева направо, вычисление только выбранной ветви.

**В отдельной копии с патчем прошли 102 теста: все 98 прежних и четыре новых.** В неизменённой 1.5 три новых тестовых метода выявляют дефект; контроль порядка эффектов проходит. У одного метода два падающих subtest, поэтому количество записей ошибок не следует считать количеством разных тестов.

Патч проверен на применимость к исходному дереву. Автоматическое повышение Python recursion limit в него не входит.

Это **проверенный проект исправления**, а не новый аттестованный выпуск AHSL. Изменённая копия намеренно не получает молча пересобранный старый манифест. Для принятия исправления в релиз нужны новая привязка исходников и обычная процедура выпуска. Исходный ZIP пользователя не изменён.

## 6. Почему это ещё не опыт Ralph / gate / декомпозиция

В пакетах находятся три разных сравнения, которые нельзя отождествлять:

| Место | Что действительно сравнивается | Чего это не измеряет |
|---|---|---|
| AHSL 1.5, `proofs.search` | `forward` и `decompose` для конъюнкций известных формул | Ralph, LLM и эффект gate |
| Эксперимент 0.3, `run_episode` | `fresh`, `history`, `plan`, `selector` | Включение/выключение `Session.admit` |
| Эксперимент 0.3, `search_study` | `fixed`, `seed_fixed`, `independent`, `hill_climb` | Декомпозицию при одинаковом gate |

В основном демо 1.5 оба доказательных режима дают одинаковый результат: плоская цель — CHECKED за один pair, вложенная — CHECKED за три pair. Это соответствует исправленной спецификации и не устанавливает преимущества планирования.

Внутренний LLM-адаптер 0.3 идёт через доверенный `Runner._run`, затем `audit_trace` и `Runner.verify`. **Он не вызывает `Session.admit` и не передаёт LLM как проверенную L12 Program.** Сам README это раскрывает. Поэтому нельзя перенести на него гарантию допуска из A12 или считать, что сравнение с gate уже проведено.

`fresh` получает текущее наблюдение; это не полная реализация Ralph с файловой памятью. `plan` добавляет один текстовый план, но не строит и не проверяет иерархическую декомпозицию. Такие условия могут быть полезными контролями, однако их надо называть в соответствии с реализацией.

Шаблон живого запуска содержит `REPLACE_WITH_PINNED_MODEL_ID` и `REPLACE_WITH_RESPONSE_MODEL_ID`. В приложенных результатах нет живой модельной кампании. Запуск имитатора ещё раз и переименование его условий не ответили бы на исходный вопрос.

## 7. Конкретный протокол следующей версии

Сначала следует зафиксировать, что означает gate: допуск нового кандидата харнеса, проверка отдельного действия или окончательная проверка ответа. В предыдущем предложении речь шла о **допуске кандидата**. Итоговый независимый judge нужен всем условиям, включая условие без gate, иначе меняется само измерение результата.

| Условие | Предлагатель | Допуск кандидата |
|---|---|---|
| R | Зафиксированный Ralph-loop | Обычное заранее описанное правило выбора baseline |
| R+G | Тот же Ralph-loop | Один закреплённый gate G |
| D+G | Предлагатель с явной декомпозицией | Тот же gate G с теми же правами, данными и правилами |

Два оцениваемых контраста:

\[
\Delta_G=U(R+G)-U(R),\qquad
\Delta_{D\mid G}=U(D+G)-U(R+G).
\]

Первый измеряет эффект gate для Ralph, второй — эффект декомпозиции при наличии gate. Три условия не оценивают полное взаимодействие двух факторов; для этого понадобилось бы четвёртое D без G. Для названных двух вопросов трёх условий достаточно.

Что требуется добавить к имеющемуся коду:

1. **Одинаковый исполнимый объект кандидата.** Например, оба предлагателя создают L12 Program, которую затем реально исполняют и оценивают. Если остаются HTTP Recipe из 0.3, нужен отдельный контракт допуска этих Recipe; `Session.admit` для них сейчас не реализован.
2. **Два реальных предлагателя.** Зафиксировать промпт и память Ralph; определить, какие подзадачи, контракты листьев и способы сборки использует D. Один текстовый план не следует молча называть проверенной декомпозицией.
3. **Полный бюджет каждого поиска.** Учитывать предложения, планирование, исполнение, gate и отказы. Одинаков должен быть доступный предел расходов; baseline не обязан искусственно тратить остаток. Билеты G12 и AST fuel не заменяют измеренную стоимость модельных обращений.
4. **Новые закрытые задачи и одинаковый независимый итоговый judge.** Все финальные кандидаты фиксируются до открытия контроля. Неудачный поиск или отсутствие принятого кандидата входят в общий результат с заранее определённым fallback.
5. **Повторение всего цикла.** Парные задачи и разбиения, одинаковая версия модели, оценка средней полезности и отдельно определённого нижнего хвоста. Повтор одного детерминированного финального solver не является новым поиском.

На G12 сильный готовый solver уже достигает 100% успеха. Поэтому эта среда подходит для проверки корректности интеграции и расходов, но имеет заведомо нулевой запас улучшения accuracy над этим контролем. Нужна содержательная задача, на которой качество предлагателя действительно неизвестно заранее.

Текущий завершённый результат — воспроизведённое ядро, воспроизведённый прежний эксперимент и проверенный проект исправления. Эмпирический вывод о пользе gate или декомпозиции на LLM пока не получен.

## 8. Комплект воспроизведения

В `AHSL-1.5-review-evidence.zip` находятся:

- этот отчёт и README;
- оба исходных ZIP с закреплёнными SHA-256;
- `review_checks.py` с ошибкой и диагностическими контролями;
- `fix-recursion.patch` с исправлением и четырьмя тестами;
- `reproduce.py`, запускающий проверки в новых каталогах без модельного API;
- полученные JSON-результаты и журналы, включая контроль новых тестов на старой реализации.

Для полного воспроизведения после распаковки комплекта:

```bash
python reproduce.py --output /absolute/path/to/a-new-directory
```

Для точного реплея сохранённого поиска требуется CPython **3.12.14**: его версия закреплена в плане 0.3. Для применения проекта исправления используется стандартная утилита `patch`. Выходной каталог должен быть новым.

Команда запускает проверки оригинала, затем применяет патч к отдельной копии и запускает её unit tests. Она не пересобирает манифест оригинального релиза. Повторный прогон численных экспериментов из журнала не объявляется новым статистически независимым опытом.
