# AHSL 1.5: repository audit

29 September 2026. Audited tree: `518d50e` (the 1.5 release after the `ahsl` → `src` rename and the English README). Runtime: CPython **3.11.15**; the release pins 3.12.14. No LLM API, network service or weight training was used. Nothing under audit was modified: every run used a temporary copy.

Evidence: `1.5-repository-audit/reproduce.py` re-runs every core finding from the repository root in about 50 s using the standard library. `1.5-repository-audit/observed-results.json` is the output of that run.

## Verdict

The core reproduces. In a directory that holds only the 33 manifest files, `verify.py` passes 98/98 tests, and the K12, wire-fuzz and benchmark numbers match §20 of `SPEC.md` exactly. `reports/benchmark.json` is byte-identical. This is also the first recorded 1.5 run on Python 3.11.

The repository as committed does not pass its own documented check, though, and three runtime defects are open:

1. `python3 verify.py` fails on a clean checkout. The documented manifest anchor no longer matches `manifest.json`, and the committed reports describe the tree as it was before the rename (A1–A3).
2. The known L12 recursion defect is still unfixed. The patch already in the repository applies after renaming its paths and passes 102/102 tests (B1).
3. New: `evaluate` changes the ledger before it checks whether a plan can still run. After any supervisor `abandon`, a single agent retry leaves a job RUNNING and the run open. Every later evaluate and admit is then blocked (B2).
4. New: fuel does not bound controller CPU. A 16 KB `run_pure` request uses 3 fuel and 9.3 s of CPU (B3).

The `experiments/llm` 0.3 snapshot runs on its own vendored 1.4 core (77/77 tests). It has one threshold bug, and its saved search and trust runs replay only on exactly CPython 3.12.14 (D1–D2).

### A. Release integrity and reproducibility

**A1. `python3 verify.py` fails on a clean checkout.**

- Where: `source_files()` in `verify.py:24` hashes every `.py` and `.json` file under the root, except `reports/` and `manifest.json`. The repository also carries `docs/` and `experiments/`, which contain 95 such files at `518d50e`, outside the 33-file release manifest. `observed-results.json` shows 96 because `reproduce.py` was already present when it ran.
- Result: the first documented command in README exits at `verify.py:287` with `Manifest differs: changed, missing, or unlisted source`. The tree at `8a6e583` (1.5 as first committed) fails the same way, so this command has never passed in this repository.
- Tests still pass when run directly: `python3 -m unittest discover -s tests` gives 98 OK. This means a reader who follows README gets a failure that looks like tampering, while the code is fine.
- Fix: limit `source_files()` to the release roots (`src/`, `tests/`, `examples/` and the top-level scripts and schemas), or exclude `docs/`, `experiments/` and `history/`. §19 of `SPEC.md` describes the manifest as covering "all `.py` and `.json` outside `reports/`", so that wording needs the same change. This audit's own evidence files add two more files outside the manifest; the same fix covers them.

**A2. The documented anchor is stale.**

- Where: `README.md:16`, `SPEC.md:627`, `reports/RELEASE-REPORT.md:58` and `docs/audits/1.5-audit-report.md:58` all give `01ada0969532…`.
- Cause: commit `cad1ffb` rewrote the manifest keys from `ahsl/…` to `src/…` and changed `src/types.py` and the tests. `manifest.json` at HEAD therefore hashes to `4eda0baa675e0a05a5b399091d2b6fc32f38cfcdf766d64220cdcecac64f7ced`.
- Result: even with the release files isolated, the documented command exits with `External manifest anchor mismatch`. With the current digest it passes.
- The per-file hashes in `manifest.json` are internally consistent. However, no trusted channel attests the new digest, so HEAD is not the attested 1.5 archive (`AHSL-1.5.zip`, `cd2f1ff9…`, kept under `docs/reviews/1.5-review-evidence/inputs/`).
- Fix: either anchor HEAD as a new release identity and update the four citations, or state that HEAD is a renamed working tree and that the anchor applies only to the archive.

**A3. The committed reports describe the tree before the rename.**

- `reports/verification.json` records `manifest_sha256 = 01ada09…`.
- `reports/replay-determinism.json` records `90ea111a…`, but HEAD produces `9f253785…` under all three hash seeds.
  - The pre-rename tree still gives `90ea111a…` on 3.11.15, so the rename caused the change, not the Python version.
  - The fixture binds `cid('Manifest', …)` into the mission, and the mission is in the snapshot.
- `reports/demo.json` changes plan and assignment IDs for the same reason.
- `benchmark.json` is byte-identical, and every count (tests, K12, fuzzers, demo totals) is unchanged.
- `reports/file-sha256.json` is self-consistent but vouches for the old run.
- `mutation-checks.json` can never match byte for byte, because it embeds temporary directory names and version-specific traceback text.

### B. Runtime defects in `src/`

**B1. The L12 host-stack limit is reached before the language's depth limit (known, still open).**

This was reported in `docs/reviews/1.5-execution-review.md` §2 and has not been fixed.

- Cause: `execute` recurses in Python (`src/language.py:175-223`). A loop at L12 depth 62 (limit 64), wrapped in 16 typed `let`s, raises `RecursionError`. Twelve `let`s still run.
- On the wire, `run_pure` answers SCHEMA.
- In G12, `Runner._run` catches only `Rejected` (`src/environment.py:282`), and `_dispatch` turns the error into SCHEMA (`src/api.py:74`). The state after that:
  - the candidate job stays RUNNING, with `open_runs=1`;
  - a retry returns PHASE;
  - a new `propose` returns PHASE until a supervisor calls `abandon`.
- The patch `docs/reviews/1.5-review-evidence/fix-recursion.patch` still applies at HEAD once `ahsl/` is rewritten to `src/`. It passes 102/102 tests and makes the reproduction evaluate to DONE/DONE. Merge it as a new release, not under the old manifest.

**B2. `evaluate` changes the ledger before checking that the plan can run.**

- Where: `Session.evaluate` (`src/admission.py:236-278`) does these steps in order:
  1. `start_run`;
  2. `reserve`;
  3. checks that the phase is not SEALED or CANCELLED;
  4. `dispatch`;
  5. calls `runner.run`.
- `Runner._run` rejects a fenced assignment with PHASE at `src/environment.py:259`, but only after step 4.
- Result: re-evaluating an abandoned plan is one ordinary agent request, and it leaves:
  - a job RUNNING that never executed, holding one reserved ticket (`free` 24 → 23);
  - `open_runs=1`;
  - `active_plan` pinned to the abandoned plan.
- After that, `evaluate` and `admit` of every other plan return PHASE until a supervisor calls `abandon` again.
- The SEALED/CANCELLED check (step 3) also runs after `start_run`, so it wedges the session in the same way.
- Why it matters: `abandon` is the documented recovery for B1. The natural client retry undoes it, and the harness wastes wall time and one of the four lifetime plans.
- Fix: before `start_run`, check every assignment of the plan (not fenced, not SEALED or CANCELLED, not RUNNING without a receipt), or mark abandoned plans as terminal.

**B3. Fuel does not bound controller computation.**

- Cause:
  - `evaluate` charges one fuel unit per AST node (`src/language.py:189-190`).
  - A builtin call costs one unit whatever its input size. `pareto` (`src/decisions.py:28-35`) is O(n²·d).
  - `invoke` also re-runs `value_ok` on every argument (`src/language.py:180-181`) and deep-copies builtin arguments (`src/language.py:220`), at no fuel cost.

Measured on one `run_pure` request, using n identical points:

| Points | Request bytes | fuel_used | Wall time |
| ---: | ---: | ---: | ---: |
| 1024 | 4,364 | 3 | 0.61 s |
| 2048 | 8,460 | 3 | 2.48 s |
| 4096 | 16,652 | 3 | 9.31 s |

- Repeated calls through binary recursion cost about 22 fuel per `pareto` call (4 calls: 76 fuel, 2.4 s at n=1024).
- The 100,000-fuel cap therefore allows about 4,500 calls. That extrapolates to about 45 min at n=1024 and about 11 h at n=4096 for one 17 KB request. These two durations were not measured.
- The same program runs as a G12 candidate: 50,000 fuel per episode and level in `evaluate`, then again in `Evaluator.assess` during `admit`. In D12 the database stays `pending` for the whole time.
- `SPEC.md` does say that fuel counts AST nodes, not CPU. But §17 presents the 1024-request limits as a controller-compute bound that "also applies to run_pure/check_proof". No such per-request bound holds.
- Fix: charge fuel in proportion to the canonical size of builtin arguments (n² for `pareto`, n·m for `plurality`/`borda`), or cap builtin input sizes. Also add a wall-clock or step limit per request.

### C. Lower-severity items

**C1. `check()` is not total.**

- Unhashable values raise a raw `TypeError` instead of `Rejected`:
  - `var.name`, `call.name` and `get.field` (`src/language.py:64,83,109`);
  - `entry` (`src/language.py:49`);
  - mixed-type `levels` in `create_mission` (`src/obligations.py:149`).
- The broad `except` in `_dispatch` maps these to SCHEMA on the wire. Direct callers see raw exceptions, including `Session.restore_integrity` on a snapshot. The 1.4 service-registry fix aimed for structured rejections in exactly these cases.

**C2. `improve` is measured against the parent only.**

- `retain` accepts a release that is worse on every cost axis (`src/admission.py:366-367`).
- On levels 1–3:
  1. a solver padded with a 2 KB unused literal is accepted in `retain` (normalized bytes 1257 → 3336);
  2. the original solver is then accepted as `improve` with `cost_strict=true` (3336 → 1257).
- Net result: the active program is the original baseline, two of the four lifetime plans are gone, and a decision says "strict improvement".
- Nothing breaks, but a count of improve decisions does not measure progress. Either compare against the best cost vector published so far, or document this next to §12.3.

**C3. §12.1 of `SPEC.md` (line 318) still shows `SUCCESS_THEN_PARETO_COST_1`.** The code and §12.3 use `_2`, and the recursion patch already includes the fix.

**Checked and found sound:**

- Canonical codec, decode round-trip and duplicate-key rejection.
- K12 invariants and role mapping.
- The D12 fencing sequence: pending blocks `restore` and `open`, and restore increments the revision.
- Alpha normalization: shadowing, `let` in value position, and parameter-order preservation. No capture was found.
- Soundness of the F2 rules; formula sizes stay polynomial in the input.
- `pycodestyle` 2.15.0 reports nothing on `src tests *.py`.

The README `DurableSession` example runs as written.

### D. `experiments/llm` (0.3 on its vendored 1.4 core)

**Status:**

- `python3 experiments/llm/verify.py` passes 77/77.
- All 15 vendored `experiments/llm/ahsl/` modules match `core-origin.json`, and all 51 `source-manifest.json` entries match. The root rename did not touch the package.
- `unittest discover` from the repository root fails with five import errors: `verify.py` is the only entry point.
- The fixture campaign replay is COMPLETE, 48/48.
- Every `file-sha256.json` entry (3 + 3 + 246 files) matches the file on disk. `summary.json`, `counts.json` and `RESULTS.md` recompute exactly from `events.jsonl`.

**D1. Boundary cases of `bad_search` are misclassified.**

- Where: `llmbench/search_statistics.py:52-53` computes `failure_rate = 1 - successes / holdout_tasks` as a float and compares it with `rat(failure_threshold)`, an exact rational.
- Examples:
  - 2 of 3 successes, threshold 1/3: `0.33333333333333337 > 1/3` is True, while the exact comparison gives False;
  - 3 of 5 successes, threshold 2/5: also True, exact False.
- The shipped configuration (4 tasks, threshold 1/4) is not affected, so the saved results stand.
- Fix: `Fraction(holdout_tasks - successes, holdout_tasks)`.

**D2. Replay requires exactly CPython 3.12.14.**

- Where:
  - `llmbench/search_protocol.py:25-27,92` compares `sys.version_info[:3]`, so on 3.11.15 the shipped search replay is refused with STALE.
  - `llmbench/trust.py:53-54,274-277` embeds the version in the checker definitions, so the trust-ledger replay fails with INTEGRITY. That error reads as tampering.
- The content itself reproduces on 3.11. With only the identity check patched:
  - the search replay is COMPLETE (1384 events, summary digest equal to `replay.json`);
  - the trust state digest matches.
- The package README says "Python 3.11+".
- Fix: report a version mismatch as STALE, and either state the exact version requirement for replay or pin the version as metadata rather than as identity.

**D3–D7.** These are low-severity items from a delegated pass. They were reproduced in scratch copies and the cited code was re-read, but they are not in `reproduce.py`.

- **D3:** `Budget.settle` calls `integer(actual)` outside the `try` in `llmbench/adapter.py:110-117`.
  - Trigger: absurd provider usage (for example `prompt_tokens=2**62`).
  - The overflow escapes before `call_end` is journaled, so the run's own journal no longer replays (INTEGRITY).
- **D4:** key redaction in `llmbench/http_worker.py:37` replaces only the exact key bytes. A JSON-escaped echo of the key in an error body is stored unredacted in `events.jsonl`.
- **D5:** the self-checks in `llmbench/offline.py:104-107,197-209` are bare `assert`s, and `mismatches: 0` is a constant. Under `python3 -O`, wrong behaviour still reports 0 mismatches.
- **D6:** `source_manifest` in `llmbench/experiment.py` hashes `.py`/`.json`/`.md` files only. A planted `.pyc` executes while `check_sources()` still passes. This is outside the trusted-host model, but the manifest does not prove which code executed.
- **D7:** `plan.json` records neither `seed` nor `cases`, and `validate_plan` does not check that fold seeds derive from `search_seed`. A reader holding only the reports cannot re-derive the preregistered order.

Also:

- `file-sha256.json` in `search-run/` and `fixture-run/` does not cover `replay.json` or `counts.json`.
- TLS verification, redirect refusal, response-size bounds, deadline enforcement and the statistical formulas (Hoeffding, DKW, CVaR and the Bonferroni splits) were checked against the spec and hold.

## Recommended order

1. Fix A1 and settle A2/A3: either a new anchor plus regenerated reports, or a clear note that HEAD is not the attested archive.
2. Merge the B1 patch together with a B2 pre-check, and add a regression test that re-evaluates an abandoned plan.
3. Decide on B3: fuel proportional to input size or input caps, and correct the §17 wording in either case.
4. Fix D1 and make D2's error honest. Both are one-line changes.
