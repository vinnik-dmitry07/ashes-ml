# AHSL LLM experiment 0.1

Исполняемый эксперимент поверх неизменённого ядра AHSL 1.4. Его вопрос: **окупается ли предварительный выбор одного из трёх LLM-циклов при одинаковом доступном бюджете?**

Реализованы HTTP-адаптер, четыре условия, учёт всех модельных вызовов, журнал внешних эффектов, независимая проверка переходов G12, повторное воспроизведение и отчёт с неопределённостью среднего, риска и нижнего хвоста. Реальная LLM-кампания при подготовке пакета **не запускалась**: в окружении отсутствовали ключи API. Приложенные результаты используют явно обозначенный программный имитатор.

## Быстрый запуск

Python 3.11+, только стандартная библиотека. Рабочая директория — корень распакованного пакета.

```bash
python3 verify.py
python3 experiment.py run --config configs/fixture.json --output ../fixture-run
```

Папка результата должна быть новой и находиться вне исходников. В ней появляются `plan.json`, `events.jsonl`, `summary.json`. Для воспроизведения передайте сохранённый при сборе `journal_head`:

```bash
python3 experiment.py replay --output ../fixture-run --expected-head <saved-head>
```

Для приложенного прогона используйте путь `reports/fixture-run` и якорь из `reports/anchors.json`. Чтобы проверять происхождение против злоумышленника, сохраните якорь независимо от папки результата: локальный хеш сам себя не удостоверяет.

## Реальный HTTP-запуск

Скопируйте `configs/live.example.json` **за пределы** пакета, например в `../live.json`. Заполните `model`, `expected_response_model`, цены и лимиты по выбранному провайдеру. Шаблон намеренно содержит незаполненные значения; это не ценовая рекомендация.

Ключ задаётся в окружении через имя из `key_env`, по умолчанию `AHSL_EXPERIMENT_API_KEY`. Он не записывается в конфигурацию и не передаётся в текст модели.

```bash
python3 experiment.py run --config ../live.json --output ../live-run --live
```

Транспорт поддерживает HTTPS Chat Completions: `messages`, одна JSON completion, `max_completion_tokens`, не потоковый ответ и `usage.prompt_tokens/completion_tokens`. Проверяйте поддержку полей выбранной моделью. `temperature`, `reasoning_effort` и `seed` отправляются только согласно конфигурации; автоматического переключения модели, провайдера или повторных запросов нет. Лимит completion включает reasoning tokens в соответствующем API. [Официальный контракт OpenAI](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

`expected_response_model` фиксирует ожидаемое поле ответа, включая snapshot-имя, если API возвращает его. Оно не доказывает неизменность весов удалённой модели. Полный ответ сохраняется для последующего аудита, включая доступный `system_fingerprint`.

## Что сравнивается

| Условие | Контекст и дополнительные вызовы |
| --- | --- |
| `fresh` — фиксированный бейзлайн | Текущая наблюдаемая ситуация, один вызов на действие |
| `history` | Текущая ситуация и последние восемь шагов |
| `plan` | Один оплаченный вызов планирования; план затем входит в каждый шаг |
| `selector` | Один оплаченный выбор стратегии до действий; затем выбранный цикл |

Одинаковы модельный маршрут, денежный лимит на эпизод и лимит числа вызовов. Расход селектора включает выбор, планирование, действия и неуспешные обращения. Сравнение использует одинаковые задачи; порядок четырёх условий перемешивается заранее. Выбор стратегии не получает результаты конкурентов.

Это полный **онлайновый бюджет модельных вызовов**. Время всего эпизода также измеряется; стоимость локального CPU, разработки и внешнего обучения в денежную метрику не включена. Протокол не выдаёт её за полную стоимость владения.

## Границы результата

G12 — маленькая публичная среда для проверки интеграции. Текущая ситуация полностью наблюдаема, поэтому память здесь может оказаться лишней. Положительный результат на ней не обосновывает пользу селектора для программирования, RLM или самоэволюции. Будущие задачи должны давать стратегиям разные заранее доступные основания для выбора.

Адаптер использует доверенный callback `Runner._run`; LLM не становится программой L12 и не проходит `Session.admit`. Гарантии статического проверяющего AHSL не переносятся автоматически. Подробная граница доверия, формулы и правила интерпретации находятся в `EXPERIMENT.md`; ответ на аудит — в `AUDIT-RESPONSE.md`.

`build_manifest.py` обновляет привязку исходников только по явному запуску владельца. `verify.py` её проверяет, не обновляя. После изменения кода это новая версия эксперимента и новый план; смешивать её результаты со старым снимком нельзя.
