# AHSL LLM experiment 0.3

Исполняемые эксперименты поверх неизменённого ядра AHSL 1.4. Версия 0.3 проверяет **процедуру поиска**: сколько стоит обнаружить решение и как часто весь цикл оптимизации находит полезный результат на заранее скрытых задачах. Исходное сравнение трёх LLM-циклов и селектора сохранено как отдельный внутренний эксперимент.

Реализованы HTTP-адаптер, четыре условия, учёт всех модельных вызовов, журнал внешних эффектов, независимая проверка переходов G12, повторное воспроизведение и отчёт с неопределённостью среднего, риска и нижнего хвоста. Реальная LLM-кампания при подготовке пакета **не запускалась**: эта поставка подготовлена без модельных API. Приложенные результаты используют явно обозначенный программный имитатор.

Наследуемая версия 0.2 добавила исполняемый слой доверия к свидетельствам: проверку точного артефакта, версию checker’а, карантин, транзитивный отзыв, повторную проверку кэша и обучающего экспорта, независимо вычисляемый дескриптор поведения. Локальный сценарий соединяет эти компоненты. Общая память в четырёх сравниваемых LLM-циклах по-прежнему отсутствует: её включение потребует отдельного эксперимента.

Новый `search_experiment.py` повторяет направленный поиск и независимое семплирование при одном доступном бюджете. Два фиксированных контроля — затравка и сильный готовый вариант — отделяют улучшение старта от окупаемости поиска. Все выбранные кандидаты фиксируются до открытия контрольных задач. Нормативный протокол: `SEARCH-SPEC.md`.

`RESEARCH-DECISIONS.md` и `research-decisions.json` сохраняют 41 работу из пользовательской таблицы: 16 ADOPT, 9 EXPERIMENT, 15 REFERENCE, 1 DROP. Решение, переносимый компонент, проверенность источника и состояние внедрения разделены. Это реестр исследовательских решений, а не заявление о независимой проверке всех статей.

## Быстрый запуск

Python 3.11+, только стандартная библиотека. Рабочая директория — корень распакованного пакета.

```bash
python3 verify.py
python3 search_experiment.py run --config configs/search.fixture.json --output ../search-run
python3 offline.py --output ../offline-run
python3 experiment.py run --config configs/fixture.json --output ../fixture-run
```

Папка результата должна быть новой и находиться вне исходников. В ней появляются `plan.json`, `events.jsonl`, `summary.json`. Для воспроизведения передайте сохранённый при сборе `journal_head`:

```bash
python3 search_experiment.py replay --output ../search-run --expected-head <saved-search-head>
python3 experiment.py replay --output ../fixture-run --expected-head <saved-fixture-head>
```

Для приложенных прогонов используйте пути `reports/search-run` и `reports/fixture-run` и якорь из `reports/anchors.json`. Чтобы проверять происхождение против злоумышленника, сохраните якорь независимо от папки результата: локальный хеш сам себя не удостоверяет.

`offline.py` не обращается к модели. Он проверяет жизненный цикл свидетельств, все 243 сочетания статусов в небольшом графе зависимостей, 264 эпизода имитатора при разных бюджетах и отказах, а также покрытие статистических интервалов на 18 заданных распределениях Бернулли. Результаты и журналы находятся в `reports/offline-run`. Файл `reports/verification.txt` содержит полный результат 77 регрессионных тестов. Число локальных проверок не является размером выборки LLM.

Исследование поиска содержит 12 повторов каждого из четырёх методов: **24 запуска оптимизации и 24 фиксированных контроля**. Они оцениваются попарно на четырёх скрытых уровнях за повтор. Расход поиска измеряется в объявленных единицах работы имитатора, а не в долларах или FLOPs. Файлы `reports/search-run/summary.json` и `reports/RESULTS.md` содержат результаты и границы интерпретации. Закрытость обеспечена интерфейсом доверенного хоста; это не защищённый сервер с секретным бенчмарком.

## Использование слоя доверия

Нормативный контракт и минимальный пример находятся в `TRUST-SPEC.md`. Хост создаёт `EvidenceLedger`, регистрирует один из трёх встроенных проверяющих профилей и передаёт артефакты через `submit`. Потребители `TrustedMemory` и `BehaviorArchive` обращаются к актуальному состоянию доверия. Публичный тестовый ключ из автономного сценария не подходит для настоящей аттестации.

Карантин исключает свидетельство из выдачи и не заменяет его исходным текстом с меткой `ASSUMPTION`. Он блокирует зависимые свидетельства и ранее выданные дубликаты точного артефакта. Только владелец может разрешить повторную проверку; её успех создаёт новое свидетельство. Смена checker’а требует новой проверки, включая перестроение зависимых пакетов.

Этот слой исполняется доверенным Python-хостом. Он не является песочницей произвольного Python, универсальным детектором prompt injection или механизмом удаления уже усвоенного моделью знания. Экспорт обязан повторно проверяться перед последующим использованием.

## Реальный HTTP-запуск

Скопируйте `configs/live.example.json` **за пределы** пакета, например в `../live.json`. Заполните `model`, `expected_response_model`, цены и лимиты по выбранному провайдеру. Шаблон намеренно содержит незаполненные значения; это не ценовая рекомендация.

Ключ задаётся в окружении через имя из `key_env`, по умолчанию `AHSL_EXPERIMENT_API_KEY`. Он не записывается в конфигурацию и не передаётся в текст модели.

```bash
python3 experiment.py run --config ../live.json --output ../live-run --live
```

Транспорт поддерживает HTTPS Chat Completions: `messages`, одна JSON completion, `max_completion_tokens`, не потоковый ответ и `usage.prompt_tokens/completion_tokens`. Проверяйте поддержку полей выбранной моделью. `temperature`, `reasoning_effort` и `seed` отправляются только согласно конфигурации; автоматического переключения модели, провайдера или повторных запросов нет. Лимит completion включает reasoning tokens в соответствующем API. [Официальный контракт OpenAI](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

`expected_response_model` фиксирует ожидаемое поле ответа, включая snapshot-имя, если API возвращает его. Оно не доказывает неизменность весов удалённой модели. Полный ответ сохраняется для последующего аудита, включая доступный `system_fingerprint`.

## Что сравнивается во внутреннем LLM-эксперименте

| Условие | Контекст и дополнительные вызовы |
| --- | --- |
| `fresh` — фиксированный бейзлайн | Текущая наблюдаемая ситуация, один вызов на действие |
| `history` | Текущая ситуация и последние восемь шагов |
| `plan` | Один оплаченный вызов планирования; план затем входит в каждый шаг |
| `selector` | Один оплаченный выбор стратегии до действий; затем выбранный цикл |

Одинаковы модельный маршрут, денежный лимит на эпизод и лимит числа вызовов. Расход селектора включает выбор, планирование, действия и неуспешные обращения. Сравнение использует одинаковые задачи; порядок четырёх условий перемешивается заранее. Выбор стратегии не получает результаты конкурентов.

Это полный **онлайновый бюджет модельных вызовов**. Время всего эпизода также измеряется; стоимость локального CPU, разработки и внешнего обучения в денежную метрику не включена. Протокол не выдаёт её за полную стоимость владения.

## Границы результата

G12 — маленькая публичная среда для проверки интеграции. Текущая ситуация полностью наблюдаема, поэтому память здесь может оказаться лишней. Положительный результат на ней не обосновывает пользу селектора для программирования, RLM или самоэволюции. Будущие задачи должны давать стратегиям разные заранее доступные основания для выбора.

Адаптер использует доверенный callback `Runner._run`; LLM не становится программой L12 и не проходит `Session.admit`. Гарантии статического проверяющего AHSL не переносятся автоматически. Подробная граница доверия, формулы и правила интерпретации находятся в `EXPERIMENT.md`; ответ на аудит — в `AUDIT-RESPONSE.md`.

`build_manifest.py` обновляет привязку исходников только по явному запуску владельца. `verify.py` её проверяет, не обновляя. После изменения кода это новая версия эксперимента и новый план; смешивать её результаты со старым снимком нельзя.
