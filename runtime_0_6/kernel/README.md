# AHSL-Core 0.5

Нормативная исполняемая семантика: `core.py`. Полное объяснение формата и всех переходов: `SPEC.md`. Область соответствия ограничена профилем событий, не всей архитектурой самоулучшающегося агента.

Из каталога комплекта:

```bash
python verify.py
python run.py examples/manifest.json examples/conflict.json
```

Нужен Python 3.10+. Сторонние Python-пакеты не требуются. `verify.py` проверяет контрольные суммы, unit cases, заданный вручную ожидаемый результат примера и replay. Он **не запускает TLC**.

Файлы:

| Файл | Назначение |
|---|---|
| `SPEC.md` | Область, синтаксис, типы, переходы, ошибки, свойства и ограничения |
| `core.py` | Нормативная функция перехода; нет физического исполнения tools |
| `run.py` | Интерпретатор конечного доверенного журнала событий |
| `tests/test_core.py` | Проверки конфликтов, ролей, стоимости, типов и сбоев |
| `examples/` | Два конкурентных вызова с конфликтом и ожидаемый результат |
| `model/Kernel.tla` | Проверочная формальная абстракция TLA+ |
| `model/Kernel.cfg` | Точная проверенная конфигурация: три вызова, бюджет 2 |
| `verification.json` | Результаты проведённых проверок и версия TLC |
| `manifest.lock.json` | SHA-256 всех поставляемых исходных файлов, кроме самого lock |
| `AHSL-0.4-design.md` | Прежний архитектурный проект, только информативный |

Для TLC установить официальный `tla2tools.jar` release v1.7.4 по URL из `verification.json`. Из каталога `model`:

```bash
java -XX:+UseParallelGC -cp /absolute/path/tla2tools.jar tlc2.TLC -workers 1 -config Kernel.cfg Kernel.tla
```

Роли `agent/provider/supervisor` в JSON примера задаёт доверенная тестовая фикстура. Это не аутентификация и не sandbox. Реальный адаптер, durable outbox, защита файлов и независимый выпуск кандидатов требуют отдельных реализаций и проверок.

Успех finite model checking не является универсальным доказательством. Машинного refinement proof между Python и TLA+ в комплекте нет.
